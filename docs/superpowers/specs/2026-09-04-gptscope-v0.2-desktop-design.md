# GPTScope v0.2 Desktop Design

## Status

Approved direction: evolve GPTScope v0.1 into a portable ChatGPT/Codex evidence inspector with a native Tauri desktop shell while preserving the clean-room boundary and the existing CLI.

## Goals

1. Ship GPTScope **v0.2.0** with a native Tauri desktop UI for Windows and macOS.
2. Preserve the v0.1 CLI/workspace contract and existing transcript/JSONL workflows.
3. Add evidence-backed recognition for known public skills, beginning with the official OpenAI `openai-docs` skill, without claiming hidden/internal skills when evidence is absent.
4. Add a deterministic timeline model that can be shared by CLI tests and the desktop renderer.
5. Add richer ChatGPT/Codex evidence adapters that normalize transcript and JSONL text without scraping process memory or private application state.
6. Restore cross-platform CI by fixing the Windows-only CLI test path bug.
7. Add native Windows/macOS Tauri build gates before moving `main` to v0.2.0.

## Non-goals

GPTScope v0.2 will not:

- dump or inspect another process's memory;
- extract cookies, API keys, bearer tokens, credentials, or decrypted traffic;
- bypass TLS, authentication, authorization, sandboxing, or platform security;
- decompile proprietary ChatGPT/Codex binaries;
- claim access to hidden prompts, hidden skills, undisclosed token counts, or private server state;
- hook ChatGPT Desktop automatically or silently monitor files/processes.

Evidence must be explicitly supplied by the user through transcript/JSONL import, the desktop file picker, or drag/drop.

## Baseline CI repair

The v0.1 exact-head run succeeded on Ubuntu and macOS but failed in the Windows `npm test` step. `test/cli.test.mjs` derives the CLI path with `new URL(...).pathname`, which is not the portable file-URL conversion path on Windows. v0.2 changes this test harness to `fileURLToPath(new URL(...))` and keeps a regression assertion around the resolved CLI path.

## Architecture

### Portable evidence core

The persisted workspace and file-based CLI remain Node.js 22+ code. Existing modules under `src/core` and `src/importers` remain compatible.

New pure modules under `src/shared` contain no `node:*` imports and are usable in both Node tests and the browser/Tauri renderer:

- `known-skills.mjs` — public skill signatures and evidence matching;
- `adapters.mjs` — transcript/JSONL string parsing and Chat/Work/Codex surface hints;
- `timeline.mjs` — stable event ordering and timeline presentation model;
- `analyze.mjs` — in-memory analysis pipeline used by the desktop UI.

The existing `inferHarness` function consumes the known-skill matcher so CLI reports and desktop reports agree on recognized public skill evidence.

### Known public skill registry

The first curated entry is:

- id: `openai-docs`
- display name: `OpenAI Docs`
- vendor: `OpenAI`
- public evidence source: `openai/skills` curated `openai-docs/SKILL.md`
- strong signatures: literal `openai-docs`, `.system/openai-docs/SKILL.md`, `.curated/openai-docs/SKILL.md`

A match creates a `known-skill` finding with supporting event IDs. Generic `SKILL.md` references still create the existing generic `skill` finding. Registry matching is evidence-only and never treats absence as proof that a skill does not exist.

### Desktop renderer

The v0.2 renderer is static HTML/CSS/ES modules and intentionally does not require Node integration or unrestricted Tauri APIs.

User-supplied evidence is read through the browser File API from an explicit `<input type=file>` selection or drag/drop. The renderer analyzes the file content in memory, after redaction, then renders:

- evidence/session summary;
- detected surface (`chat`, `work`, `codex`, `unknown`);
- chronological event timeline;
- findings with confidence and evidence-event links;
- recognized known-skill badges, including `openai-docs` when present;
- a raw/redacted event inspector.

No arbitrary filesystem-read Tauri command is exposed in v0.2.

### UI build

`scripts/build-ui.mjs` copies the static renderer and the required pure shared modules into `dist/ui`. It fails closed if a required source file is missing and removes stale output before rebuilding.

Tauri serves only `dist/ui` as `frontendDist`, not the repository root.

### Tauri shell

The shell lives under `apps/tauri/src-tauri` and is intentionally minimal:

- Tauri crate pinned to `=2.11.5`;
- Tauri CLI pinned to `2.11.4` in `package.json`;
- no custom invoke commands in v0.2;
- CSP restricts content to local assets;
- Windows bundles: NSIS + MSI;
- macOS bundles: DMG + app;
- unsigned packages are allowed, with the README stating this explicitly.

## Data flow

1. User selects/drops a `.txt`, `.jsonl`, or `.json` evidence file.
2. Renderer reads file text with the browser File API.
3. `adapters.mjs` parses and normalizes in-memory records.
4. Strings/payloads are redacted before presentation.
5. `analyze.mjs` runs generic harness inference plus known-skill matching.
6. `timeline.mjs` creates deterministic timeline rows tied to report findings.
7. Renderer updates summary, timeline, findings, and inspector without sending evidence over the network.

## Error handling and bounds

- Desktop import rejects unsupported extensions.
- Desktop import rejects files larger than 16 MiB before reading.
- Malformed JSONL returns a bounded line-number error instead of silently skipping records.
- Empty evidence renders an explicit empty-state report.
- UI build fails on missing source assets.
- Tauri desktop is only built on Windows/macOS; Linux continues to validate the portable Node core.

## Testing

Node tests cover:

- Windows-safe CLI path construction;
- `openai-docs` strong-signature matching and no false positive for unrelated text;
- JSONL/transcript in-memory adapters;
- deterministic timeline ordering and evidence links;
- UI build output and required files;
- desktop HTML security contract (no remote scripts, no unrestricted Tauri bridge use);
- version consistency across package/Tauri config/Cargo metadata.

CI gates:

1. Node tests on Ubuntu, Windows, macOS.
2. `doctor` on all three OSes.
3. UI build on all three OSes.
4. Tauri `cargo check`/`clippy` on Windows and macOS with Rust 1.98.1.
5. Unsigned Windows and macOS native bundle builds on exact v0.2 head.

`main` must not be advanced to the v0.2 commit until these exact-head gates are green.

## Version and release contract

The release version is **0.2.0** everywhere: `package.json`, CLI help, Cargo package, and `tauri.conf.json`.

After exact-head CI is green, fast-forward `main` to the verified commit, create tag `v0.2.0`, and publish a GitHub release only from that exact `main` SHA. Release artifacts may be unsigned and must be described as such.
