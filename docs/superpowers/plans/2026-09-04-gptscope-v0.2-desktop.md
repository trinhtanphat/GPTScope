# GPTScope v0.2 Desktop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship GPTScope v0.2.0 with a native Tauri desktop evidence inspector, public `openai-docs` skill recognition, deterministic timeline analysis, restored Windows CI, and exact-head Windows/macOS desktop build gates.

**Architecture:** Keep the Node CLI/workspace contract intact. Add browser-safe pure modules under `src/shared`, a static desktop renderer built into `dist/ui`, and a minimal Tauri shell with no custom filesystem IPC. Reuse the same known-skill matcher from CLI inference and desktop analysis.

**Tech Stack:** Node.js 22 ES modules, Node built-in test runner, static HTML/CSS/JavaScript, Tauri 2.11.5, Tauri CLI 2.11.4, Rust 1.98.1, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-04-gptscope-v0.2-desktop-design.md`

## Global Constraints

- Version is exactly `0.2.0` in package, CLI help, Cargo metadata, and Tauri config.
- No process-memory scraping, credential extraction, TLS interception, auth bypass, or proprietary binary decompilation.
- Desktop reads only user-selected/dropped evidence through the browser File API.
- Desktop input size limit is 16 MiB.
- Tauri crate is pinned to `=2.11.5`; Tauri CLI is pinned to `2.11.4`; Rust CI toolchain is `1.98.1`.
- `main` advances only after exact-head Node + native desktop gates are green.
